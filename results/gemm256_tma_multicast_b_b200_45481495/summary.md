# GEMM 2-CTA B TMA multicast ablation

## Conditions

- Date: 2026-07-22
- GPU: NVIDIA B200, Vast.ai instance `45481495`, 1000 W power limit
- Definition commit: `773808c`
- Input: BF16 uniform `[0,1)` generated by the kernel's fixed hash seeds
- Output: complete FP32 C matrix through TMA stores
- Problem sizes: square M=N=K = 8192, 16384, and 32768
- CTA: `256x256`, K64, three SMEM stages, two 128-wide B pipes
- Persistent workers: 148 CTA in both variants
- Schedule: 12x12 macros at 8K/32K and 16x16 at 16K, local M-fast,
  macro N-fast, dynamic work allocation
- Measurement: one case per process, warmup 1, five timed launches, three
  independent rotated passes

The control uses independent 1-CTA TMA loads. The multicast variant fixes the
cluster shape to `(2,1,1)`, allocates two consecutive M-fast tasks per cluster,
and has rank 0 multicast B to ranks 0 and 1. Both CTAs retain independent
`tcgen05.mma cta_group::1` computation and independent A loads.

## Validation

Both variants passed the 512 pattern test with the complete FP32 output:

| variant | max abs | max rel | bad |
|---|---:|---:|---:|
| 1-CTA control | 0 | 0 | 0 |
| 2-CTA B multicast | 0 | 0 | 0 |

The compiled multicast binary contains `UTMALDG.4D.MULTICAST` instructions.

## Interpretation

For a two-CTA K64 stage, independent loads transfer 64 KiB of A and 64 KiB
of B, or 128 KiB total. B multicast retains the 64 KiB of independent A but
loads only 32 KiB of B, reducing the pair's requested input payload to 96 KiB
(25%). This traffic reduction is not automatically a throughput gain:

- At 8K, the selected tile order already reuses B effectively through L2 and
  the kernel is short. Cluster scheduling, pair synchronization, remote
  mbarrier updates, and the two-consumer reuse barrier cost more than the
  remaining memory saving, producing a repeatable 3.05% regression.
- At 16K, those costs and the traffic reduction nearly balance; multicast is
  0.53% slower.
- At 32K, the larger moving working set puts more pressure on the memory/L2
  path. The 25% pair-input reduction becomes material and multicast is 2.67%
  faster, while also reducing process variance.

This comparison intentionally measures the full practical 1-CTA-to-multicast
change. A follow-up three-way ablation should add a two-CTA clustered,
pair-scheduled, non-multicast control if cluster/scheduler overhead must be
separated quantitatively from the B-traffic saving.

GPU temperature was 34 C before and 39 C after the run. The instance was
stopped immediately after artifact download.
